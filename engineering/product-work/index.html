01

受講生向けチャットシステム

限定公開・導入準備

作った背景

受講生との会話を、必要な部屋で確認できるようにしたくて制作しました。投稿できるだけでなく、誰に見えるのか、返信を待っている会話はどれか、PCが止まったときにどうするかも決める必要がありました。

実装したこと

  • 招待・ログイン、部屋ごとの閲覧権限、添付、検索、未読・返信待ちの管理。
  • 投稿の編集・削除、セッション管理、二段階認証。
  • PC停止中の一時受付と、復帰後の取り込み。保存が確認できてから受領を返す処理。

Python / FastAPI / SQLite / HTML・CSS・JavaScript / Cloudflare Workers・D1・R2

確認したこと

  • パスワード変更による全セッションの失効。期限と一度だけ利用できる再設定処理。
  • 権限のない部屋へのアクセスを拒否する認証・権限テスト。
  • 合成データによる、一時受付 → サーバー → 保存 → 受領確認の統合テスト。
  • 通常画面と一時受付画面について、PC幅・スマートフォン幅の表示を確認。

現在の段階
限定公開し、初期導入に向けて認証・権限や運用面の確認を続けています。

根拠：認証・中継の実装、認証テスト、合成データ統合テスト、画面確認記録。原本と利用者データは非公開です。

02

記事公開・通知・履歴の自動化

自社で運用

作った背景

完成した画像を保存した後、記事にして公開し、公開できたかを確かめる作業がありました。毎回同じ操作をする部分をつなげ、途中で止まった場合も状況を追えるようにしています。

実装したこと

  • フォルダーへの保存を監視し、保存が安定してから処理を開始。
  • 日付別の記事公開、Windowsへの通知、公開履歴の記録。
  • 重複受付を防ぎ、同日分の別画像による上書きを拒否。
  • 受付・処理中・停止・公開済みを分けて表示し、復旧・保守の手順を整備。

Node.js / Python / PowerShell / C#

使いながら直していること

公開できていないのに、終わったように見える状態を避けることを重視しています。処理の履歴や停止理由を確認し、復旧と監視の方法も含めて改善しています。

関連して、会員向け学習サイトの新着記事への導線や表示も改修。生成元の想定外の変更を検知する検査と、公開対象を確認するテストを整備しています。

稼働条件
Windowsへのログオンとネット接続が必要です。24時間無停止の運用や、あらゆる障害からの無人復旧を実現したという意味ではありません。

根拠：運用README、保存・重複・状態管理の実装、復旧手順、依存ファイルの監査、運用再開の記録。記事本文や運用先は公開していません。

03

Job Radar — 求人収集・条件整理

本人が利用・改善中

作った背景

気になる求人を開いても、勤務条件が合わなかったり、前に見た募集だったりする。その確認を何度も繰り返すのがきっかけでした。求人を取り込んでから、条件の確認と候補の整理までを一つにまとめています。

実装したこと

  • 読み取り専用OAuthによるGmail求人通知の取得と、公開求人APIからの取り込み。
  • 処理済み識別子・URLによる重複防止、保存・応募済み・非表示の状態管理。
  • 雇用形態・職種・勤務条件の絞り込み、経歴と条件を照合する整理。
  • 日次更新と手動更新。通信間隔の共有と、更新の同時実行を防ぐロック。

Python / SQLite / Gmail API / OAuth / HTML・CSS・JavaScript

間違えないための扱い

  • 求人通知の要約を、募集本文の確認済み情報にしない。
  • 取得失敗と募集終了を分け、失敗時は前回の本文・成功日時を維持。
  • 通知内の別求人から、会社名や条件を取り違えて流用しない。
  • 実務の年数と自社制作の経験を分け、足りない条件を推測で埋めない。

収集の範囲
Indeed・Greenの検索結果を無人巡回する仕組みではありません。通知・公開APIによる取り込みと、人がAIの調査支援も使って募集内容を確認する作業を分けています。自動更新にはPCとアプリの稼働が必要です。

根拠：取込・更新CLI、通知解析、重複・勤務条件・状態保持のテスト、アプリREADME。求人・経歴・認証情報は非公開です。

05

水鏡相場録 / FX過去検証・チャートリプレイ

本人用ローカル版・検証中

作った背景

過去のチャートを少しずつ進め、その時点で売買をどう判断するかを練習するアプリです。自分が検証で使う操作をまとめ、MT4・MT5の起動やログインに依存せず、途中の記録から再開できるようにしました。

実装したこと

  • 4画面・9種類の時間足。1本・10本の足送りと巻戻し、速度を変えた再生、拡大・移動、指標の設定。
  • USDJPYの仮想売買。成行・指値・逆指値、損切り・利確、スプレッド・手数料を含む損益計算。
  • CSV・MT5形式TSVの取込と検査。IndexedDBへの保存、データ別の練習記録・画面設定、JSONでの保存・復元。
  • 勝率・損益・資産推移・最大ドローダウンなどの集計、取引CSVと操作履歴の出力。

JavaScript ES Modules / HTML・CSS / Canvas 2D / Node.js / IndexedDB・localStorage

確認したこと

  • 既知の1分足までで上位時間足を作り、未来の値を参照しないこと。
  • 巻戻し後の取引再構成、仮想注文と約定、保存・再開、同じデータの照合。
  • CSVの不正値・重複、保存失敗、同時更新による競合、配布物からの非公開データ除外。
  • ローカル通常版と確認版の起動・保存先の分離。Chromeで4画面表示と再起動後の設定保持を確認。

現在の範囲
USDJPYの1分OHLCに基づくシミュレーションです。ティック単位の値動き、変動スプレッド、複数建玉・複数通貨、実際の約定の再現は対象外です。本人用ローカル版と本人限定クラウドを用意しており、一般向けの販売実績としては掲載していません。

根拠：リプレイ・注文・保存処理の実装、2026年10月30日の自動テスト160件成功記録とChrome確認記録。価格データ原本・練習記録・非公開コードは掲載していません。

06

YouTubeデータ分析アプリ

読取・表示を確認

作ったもの

動画の結果を継続して振り返るため、YouTube Data API・Analytics APIを読み取り専用で利用するデスクトップアプリを制作しました。

  • 7日・28日の比較、動画別分析、日別CSV、データ不足・欠測の表示。
  • OAuth接続、データのローカル保存、定期取得。認証情報はWindows DPAPIで保護。
  • CTRなどAPIで揃わない項目を扱うためのCSV取り込み。

Python / tkinter / Pillow / YouTube Data・Analytics API / OAuth / Windows DPAPI

確認と、これからの部分

実際のOAuth接続で読み取りと画面表示を確認し、集計・表示などの自動テストを実施しました。画面の分析コメントは、条件分岐と定型文によるルールベースです。

現在の範囲
LLMによる分析・学習は実装していません。CTRのAPI自動取得、A/Bテストの自動勝者判定、収益分析も対象外です。実際のStudio CSVとの照合や、認証期限切れ後の再接続は継続確認が必要です。

根拠：API接続・分析処理のコード、自動テスト、実アカウントでの表示確認記録。チャンネル名・視聴データ・認証情報は非公開です。

画面キャプチャ・注釈編集ツール

Windows実機で検証

作ったもの

画面を撮って説明を添え、そのままやり取りに使えるWindowsアプリを制作しています。実際に使いながら、ウィンドウを広げたときの重さや、画像を渡すときの操作を改善しました。

  • 範囲指定の撮影、PNG保存、注釈編集、Undo・Redo。

  • 背景の再利用と不要な再描画の削減によるリサイズ処理の修正。

C# / .NET Framework / WinForms / FFmpeg / PowerShell

確認したこと

合成画像を使った保存・再読み込み、履歴からのドラッグ、Windows実機での無音録画を確認しました。配布ビルドの一致確認も行っています。

未確認・未実装
マイク録画、印刷、倍率の異なる複数ディスプレイでの動作は未確認です。保存した注釈を後から編集し直すための独自形式は、まだ実装していません。

根拠：README、実装、検証記録、配布物の照合記録。実際に撮影した業務画面は公開していません。
